# 展示会スタッフ専用 注文管理

NEO TOKYO 2026 を想定した、登録スタッフ専用のスマホ優先注文管理ツールです。商品検索から注文登録、お客様控えQR、本社共有、後日受取、会計・受け渡し、日付別の提出・印刷までを扱います。

## 完成版の主な機能

- 3,861商品の最新版マスターを品番・商品名で検索
- 商品追加専用のフル画面（検索バーを上部、固定入力キーを検索バー直下、進むボタンを下部に固定）
- 検索結果から商品を追加しても候補を閉じず、同じ品番群を続けて複数追加（入力クリア時だけ候補を閉じる）
- 画面を動かさず品番を入力できる固定入力キー（スマホ型3列テンキー／英字QWERTY切替）
- 固定入力キーは「◀ 左」「右 ▶」ボタンで片手操作しやすい位置へ切替（選択位置を端末に保存）
- 国内通常注文、即時現売り、後日会場受取、ホテル配送、指定先配送
- 現売りの「商品の渡し方」は4種類を1列で表示
- 現売りは渡し方を自動選択せず、1〜4から必ず明示選択
- 「要対応」「受取待ち」「完了」の3フォルダで迷わず管理
- 本社未共有・受取待ち・未会計の件数カードは3フォルダを横断し、カードの件数と表示件数が一致
- 店舗、受付番号、電話、品番、商品名を3フォルダ横断で検索
- 状態変更後は矛盾する検索・絞り込みを解除し、移動先の注文を即時表示
- 後日受取・配送は「本社共有済み」を明示
- カードに受付日時、詳細に作成日時・最終更新日時を表示
- 「提出・印刷」で本日・指定期間・全期間を選び、件数・点数・金額・未同期・未完了を出力前確認
- 未同期注文を含む展示会最終提出を停止。通常注文の伝票出力と個別印刷は継続可能
- 注文カードの「印刷対象」表示は省略し、印刷メニューから保存済み注文をまとめて出力
- 本番ログイン画面は登録スタッフのログインだけを表示し、匿名の端末モードは非表示
- ログイン後の通信失敗時は端末へ保存し、未同期件数を明示して通信復旧後に自動同期
- 登録スタッフ全員で同じ注文画面を共有（3秒ごと・画面復帰時・通信復帰時に自動同期）
- 「完了」に入った注文を含め、注文詳細から商品・お客様情報・受け渡し内容を修正
- 本社共有が必要な注文は、共有状態ボタンの直前から注文書を印刷・PDF保存
- 登録完了後は「お客様控えQRを表示」を主操作にし、準備中・準備完了・失敗を明示
- QR失敗時も注文は保存済み。同じ注文・同じ送信IDから再試行し、二重登録を防止
- お客様へQRコードを提示し、スマートフォンに表示された注文控え画像を長押しで保存
- お客様控えのお客様名には「様」を自動付与（入力済みの敬称は重複させない）
- 注文作成画面を途中で閉じても入力内容を再開でき、確認後に破棄して新規注文も開始可能
- 卸屋・帳合先の「その他」は具体名を必須保存。電話番号は海外形式を許容しつつ想定外文字を警告
- お客様控えには展示会名・本社共有・社内対応状態・受け渡し・社内担当・卸屋・社内備考・URL・日時・案内文を載せず、注文内容だけを表示
- 韓国展示会ツールを基準にした、ロゴ・注文情報・商品明細・合計が1枚で読める控え／印刷レイアウト
- 一括印刷は注文区分ごと、同じ区分内では卸屋・帳合先ごとに自動整列

## 起動

ES Modules とCSV読込を使うため、ファイルを直接開かずHTTPサーバーから起動します。

```powershell
python -m http.server 4173 --bind 127.0.0.1
```

ブラウザで `http://127.0.0.1:4173/` を開きます。本番設定は `online-config.js` の `onlineEnabled: true` で、登録スタッフのログインだけが表示されます。

ローカルのUI回帰確認に限り `http://127.0.0.1:4173/?local-development=1` を使用できます。この内部経路は `127.0.0.1` 限定で、本番画面に入口はありません。注文登録APIは許可済み本番Origin以外からの作成を拒否するため、ローカル確認から本番注文は作成されません。

## 展示会での運用フロー

### 国内通常注文

店舗、電話番号、卸屋・帳合先、受注担当者を入力して登録すると「完了」に保存されます。お客様控えQRを表示した後、帰社後に「提出・印刷」から国内通常注文だけをまとめて出力します。

### 現売り対応

1. 在庫あり・その場渡し：会計と商品のお渡し完了で登録し、そのまま「完了」
2. 翌日・翌々日受取：本社未共有なら「要対応」、共有済みなら「受取待ち」、会計・お渡し後に「完了」
3. ホテルへ配送：本社未共有なら「要対応」、共有済みになった時点で本社へ引き継ぎ、「完了」
4. 指定住所へ配送：本社未共有なら「要対応」、共有済みになった時点で本社へ引き継ぎ、「完了」

このツールはSlackへ自動送信しません。本社共有欄の「印刷・PDFで本社へ共有」で注文書を用意し、各自Slackなどで実際に共有した直後に「本社共有済み」を押します。

## 提出・印刷

- 「国内通常注文をまとめて印刷」：帰社後の伝票打ち提出用
- 「展示会の全注文データをPDF・印刷」：展示会終了後の提出用。注文一覧と全明細を出力
- 注文詳細の「この注文をPDF保存・印刷」：個別確認用
- 注文詳細の「お客様控えQR・画像」：お客様のスマートフォンへQRを表示し、韓国展示会ツールと同じように画面上の控え画像を長押しで保存

一括出力は `createdAt` / `created_at` を日本時間へ正規化し、`本日`、開始・終了を含む`日付を指定`、日付不明の旧注文も含む`全期間`から選びます。表紙には展示会名、対象受付日、出力日時、注文数、点数、合計を表示し、一覧には受付日時を載せます。未同期が1件以上ある最終提出は出力できません。

ブラウザの印刷画面で「PDFに保存」を選ぶとPDFにできます。メールやSlackとの連携はありません。

注文の内容に誤りがあった場合は、「要対応」「受取待ち」「完了」のどのフォルダでも注文詳細を開き、「この注文を修正」から訂正できます。登録スタッフでログイン中の修正は全スタッフへ同期されます。

## Supabase同期

プロジェクト参照IDは `qdexhwgzawisiklekfzm` です。公開版では登録済み・有効なスタッフでログインすると、同じ展示会の注文と状態更新を全スタッフで共有します。3秒ごとの同期に加え、画面へ戻った時と通信が復帰した時にも直ちに再同期します。上部には同期中、最終同期時刻、未同期件数を表示します。

ログイン前に完全オフラインの場合は注文管理へ進めず、再接続案内を表示します。ログイン済みなら通信障害中も端末保存を継続し、復旧後に既存の未同期キューを自動送信します。既存ローカル注文・公開トークンは削除しません。service role key、個人のアクセストークンなどの秘密情報をブラウザ側ファイルやGitへ保存してはいけません。
