# 展示会スタッフ専用 注文管理 v1

NEO TOKYO を想定したスマホ優先の本番仕様です。

## 重要な設計
- 起動直後はスタッフ管理画面。
- 新規注文は「商品 → 注文方法 → 必須情報」の3ステップ。
- 国内通常注文：店舗名・電話番号・帳合先・受注担当が必須。
- 現売り即時：受付番号なし。会計＋お渡しを1ボタンで完了可能。
- 後日受取／ホテル配送／指定先配送だけ受付番号を使う。
- 会計、商品準備、お渡し／発送は別データで保持。UIには次の操作だけを表示。
- 未会計の商品引渡しは通常フローでは発生しないよう、次アクションを会計優先にする。
- スマホで「今日受取／明日以降／未会計」が常に見える。

## 既存システムの再利用
`online-config.js` は現在の韓国展示会と同じ Supabase の publishable key を設定済みです。
既存の `exhibition_orders` と `exhibition_staff` を再利用し、新しい業務項目は `order_data` JSON 内に `schemaVersion:2` として保存します。
これにより韓国ツールの既存注文を壊さず併存できます。

新規登録は既存 Edge Function `exhibition-order` を利用します。スタッフ側の更新はログイン済み REST 更新を利用します。

## 本番切替
1. `online-config.js` の `onlineEnabled` を `true` に変更。
2. `eventId`, `eventName`, `eventDate` を対象展示会に設定。
3. `product_master.csv` を国内用の商品マスターへ差し替え。列は `code,name,price`。
4. GitHub Pages にフォルダ内ファイルを配置。
5. 既存のスタッフアカウントでログイン確認。
6. Supabase Edge Function `exhibition-slack` をデプロイし、Secret `SLACK_WEBHOOK_URL` を設定。

## 注文書提出
国内通常注文の主ボタンは「登録して注文書提出」。登録と同時に対応済みにできます。
PDFはブラウザの印刷機能から「PDFに保存」を使います。
Slack Edge Function を有効にすると提出・状態更新を Slack に通知します。

## 通信障害
注文は先に端末へ保存し、その後オンライン送信します。オンライン送信に失敗すると「未同期」と表示されます。
即時現売り・国内通常注文は端末内で継続できます。
後日受取等は一時的に `仮-xxx` 番号を表示し、オンライン作成成功後にサーバー受付番号へ置換します。
